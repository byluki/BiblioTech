Lo que construimos

Una solución web donde catálogo, préstamos y socios están en un solo lugar.

A · La web

Frontend

HTML, CSS y JavaScript. Catálogo, carrito de reservas, ficha de cada libro y un panel distinto para cada rol.

B · La API

Laravel

Valida cada regla del negocio. Inicio de sesión con tokens de Sanctum y permisos por rol.

MySQL

025.6
EJE

La vida de un ejemplar

Un libro puede tener varias copias físicas. Cada copia pasa por estos estados y el sistema no deja saltear pasos.

Además existen extraviado y fuera de circulación, para copias perdidas o retiradas.

Cada cambio ocurre dentro de una transacción, así dos personas no pueden llevarse la misma copia al mismo tiempo.

025.04
API

Qué pasa cuando Lucía toca “Reservar”

Un clic en la página es un pedido a la API. Antes de guardar nada, el pedido pasa por estos controles.

  1. Navegador POST /api/reservas

    El JavaScript de la página manda el pedido con el token de Lucía.

  2. nginx :8000

    Recibe el pedido y se lo pasa a Laravel (PHP-FPM).

  3. Sanctum auth:sanctum 401

    Comprueba el token. Sin una sesión válida, el pedido no sigue.

  4. Validación 422

    Revisa que el socio y el libro existan y que la fecha no sea pasada.

  5. Reglas del negocio 403 422

    Se reserva solo a nombre propio, con el socio activo y una vez por libro, salvo que sea un centro educativo verificado.

  6. MySQL transacción

    Si hay un ejemplar libre, queda para retirar por 2 días. Si no, entra a la fila como pendiente.

  7. Historial

    Se anota quién reservó y cuándo.

  8. Respuesta 201 Created

    La API le devuelve la reserva a la página, que muestra el aviso.

025.04
SEG

Seguridad y sistemas

Una biblioteca guarda cédulas, teléfonos y deudas. Así cuidamos esos datos.

01Contraseñas ilegibles

Se guardan con hash (bcrypt): ni nosotros podemos verlas. Exigen 8 caracteres, mayúscula, minúscula y número.

02Sesiones con token

Cada inicio de sesión recibe un token de Sanctum que se borra al salir. Un usuario dado de baja no puede entrar.

03Permisos en el servidor

Cada ruta de la API revisa el rol. Esconder un botón no alcanza: si alguien pide algo que no le toca, la API lo rechaza.

04Base de datos cerrada

MySQL y phpMyAdmin solo responden dentro de la propia máquina. Desde la red no se puede llegar a ellos.

05Todo queda registrado

El historial guarda quién prestó, cobró o anuló cada cosa. Libros y socios se dan de baja sin perder su historia.

06Datos validados

La API revisa cada dato: cédulas, teléfonos, montos y fechas. En producción los errores no muestran detalles internos.

Fondo blanco: se puede abrir desde la red. Fondo gris: solo funciona adentro. Son 5 contenedores que se levantan con un solo comando.
